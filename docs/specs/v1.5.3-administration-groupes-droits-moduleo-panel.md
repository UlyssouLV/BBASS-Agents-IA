# V1.5.3 — Administration des groupes et droits Moduléo depuis le Panel d'administration

Parent GitHub : [#209](https://github.com/UlyssouLV/BBASS-Agents-IA/issues/209).

## Problem Statement

- **Les groupes et droits Moduléo se gèrent hors écran.** Depuis la 1.5.1, la copie des droits ([ADR-0018](../adr/0018-droits-moduleo-appliques-par-bbass.md)) vit dans un fichier versionné rechargé à chaque démarrage, et le rattachement d'un compte à ses groupes Cogeo / Planning et à son utilisateur Moduléo passe par un script. Un compte administrateur du cabinet ne peut pas créer un groupe, cocher ses droits comme dans Moduléo, ni rattacher un collègue sans intervention technique.
- **Le fichier écrase les groupes au boot.** Tant que `catalogue.json` réécrit les droits des groupes qu'il liste, une administration interactive serait perdue à chaque redémarrage.

## Solution

**Une partie Moduléo dans le Panel d'administration**, sous un nouvel onglet **Outils** (sous-onglet **Moduléo** — place laissée pour d'autres outils plus tard). Le compte administrateur y gère :

1. **Les groupes** Cogeo et Planning : créer, renommer, éditer les droits (arborescence façon Moduléo, conditions Planning), supprimer seulement s'il n'est rattaché à aucun compte.
2. **Les rattachements** : pour chaque compte, groupe Cogeo, groupe Planning, utilisateur Moduléo (recherche par nom, comme le script actuel).
3. **Un journal minimal** : date, admin, action, cible — consultable dans le même onglet, sans export en 1.5.3.

**Source de vérité** ([ADR-0019](../adr/0019-groupes-moduleo-administres-en-base.md)). `catalogue.json` ne sème / met à jour que le **catalogue des cases** (libellés, arborescence). Les **groupes et leurs droits accordés** vivent **uniquement en base**, édités par le Panel ; le démarrage ne les écrase plus. Si la base n'a encore aucun groupe, on sème encore **Admin** (Cogeo + Planning) une fois. Les installs 1.5.1 conservent leurs groupes et rattachements. « Tous droits (dev) » reste hors Panel (création de dev comme aujourd'hui). Le script `affecter_groupes_moduleo.py` n'est plus la voie officielle d'administration.

**Pas de détection automatique de dérive** vs Moduléo (l'API n'expose pas la matrice d'un groupe). Quand Moduléo ajoute ou retire une case, un déploiement met à jour `catalogue.json` ; l'admin coche ensuite les groupes concernés dans le Panel.

Le garde des droits et les outils Moduléo du chat restent ceux de la 1.5.1 : un changement de groupe ou de rattachement vaut à partir du tour suivant.

## User Stories

1. En tant que compte administrateur, je veux ouvrir Outils → Moduléo dans le Panel, afin de gérer les droits Moduléo sans script ni fichier.
2. En tant que compte administrateur, je veux créer un groupe Cogeo ou Planning, afin de coller à l'organisation du cabinet.
3. En tant que compte administrateur, je veux renommer un groupe, afin de suivre un renommage Moduléo.
4. En tant que compte administrateur, je veux cocher / décocher les droits d'un groupe dans une arborescence comme dans Moduléo, afin de recopier fidèlement la matrice.
5. En tant que compte administrateur, je veux poser les conditions Planning (participation, activité, créateur) sur une action, afin de respecter les règles Moduléo.
6. En tant que compte administrateur, je veux supprimer un groupe sans rattachement, afin de retirer un groupe obsolète.
7. En tant que compte administrateur, je veux qu'on me refuse la suppression d'un groupe encore rattaché, afin de ne pas orpheliner des comptes en silence.
8. En tant que compte administrateur, je veux rattacher chaque compte à un groupe Cogeo, un groupe Planning et un utilisateur Moduléo (ou aucun), afin que le chat n'expose que ce que son groupe autorise.
9. En tant que compte administrateur, je veux rechercher l'utilisateur Moduléo par nom, afin de ne pas saisir un id.
10. En tant que compte administrateur, je veux voir un journal minimal des changements (qui, quand, quoi, cible), afin de savoir qui a modifié les droits.
11. En tant que compte administrateur, je veux qu'un redémarrage de la VM ne réécrase pas les droits des groupes que j'ai réglés dans le Panel, afin que l'administration tienne.
12. En tant que compte administrateur, je veux qu'une nouvelle case ajoutée au catalogue versionné apparaisse dans le Panel sans écraser mes groupes, afin de pouvoir la cocher ensuite.
13. En tant que collaborateur, je veux que mes outils Moduléo suivent mon rattachement dès le tour suivant un changement admin, afin que les droits réels s'appliquent.
14. En tant que compte non administrateur, je veux que l'API d'administration Moduléo me soit refusée, afin que seuls les admins changent les droits.
15. En tant que compte administrateur qui valide cette version, je veux que la suite pytest existante reste verte, afin de vérifier qu'aucune fonctionnalité n'a régressé.

## Implementation Decisions

- **UI poste.** Panel : onglet **Outils** contenant un sous-onglet **Moduléo** (autres sous-onglets outils plus tard). Section groupes + section rattachements comptes + liste du journal. Même stack que Comptes / Consommations (React, shadcn).
- **API vm-centrale.** Routes admin (jeton compte administrateur) pour : catalogue (lecture arborescente), groupes (CRUD borné), droits d'un groupe (remplacement de l'ensemble accordé + conditions Planning), rattachements (lecture / mise à jour), journal (liste récente). Contrat HTTP du poste élargi en conséquence.
- **Boot.** `charger_catalogue` met à jour les cases ; retire une case sortie du fichier (et des groupes qui l'avaient) ; **ne remplace plus** les droits des groupes listés dans le fichier. Semence Admin Cogeo+Planning seulement si aucun `GroupeModuleo` n'existe. Groupes créés ensuite : Panel uniquement.
- **Script.** `affecter_groupes_moduleo.py` retiré ou relégué hors voie officielle (doc : passer par le Panel). `creer_groupes_dev` inchangé (hors Panel).
- **Journal.** Table des événements admin Moduléo (date, identifiant admin, action, cible) ; pas d'export.
- **ADR-0019.** Source de vérité des groupes = base administrée par le Panel ; le fichier garde le catalogue des cases (amende la conséquence « fichier versionné » de l'ADR-0018 pour la 1.5.3).
- **Glossaire.** « Groupe Moduléo » mis à jour (admin Panel) ; « Journal des droits Moduléo ».
- **Hors dépendance 1.5.2.** Cette version part de `main` (1.5.1) ; l'écriture Moduléo n'est pas un prérequis.

## Testing Decisions

Coutures HTTP (`TestClient`, vraie base de test), prior art `test_comptes.py`, `test_groupes_moduleo.py`, `test_garde_droits_moduleo.py` :

- API admin Moduléo : groupes (créer, renommer, droits, supprimer avec / sans rattachement), catalogue, rattachements (résolution utilisateur par nom), journal.
- Auth : non-admin / sans jeton refusés.
- Boot : cases mises à jour sans réécriture des droits de groupes existants ; Admin semé seulement base vide ; case retirée du fichier retirée des groupes.
- Effet chat : après changement via API, tour suivant aligné garde / outils proposés.
- Pas de test de composants React du Panel.

## Out of Scope

- Détection automatique de dérive de la copie vs Moduléo.
- Page doc-site « administration des groupes et droits » (hors version).
- Une clé d'API par collaborateur ; restriction d'accès par affaire ; Agents par pôle.
- Export du journal ; édition du catalogue des cases depuis le Panel.
- Écriture Moduléo (1.5.2, branche parallèle).
- Autres sous-onglets de Outils au-delà de Moduléo.
