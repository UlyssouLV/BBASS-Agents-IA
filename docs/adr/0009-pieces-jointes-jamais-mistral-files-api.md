# Pièces jointes : jamais stockées durablement chez Mistral

À partir de la [1.1.2](../specs/v1.1.2-pieces-jointes.md), une pièce jointe (PDF, Word, Excel, image) n'est **jamais stockée durablement** chez Mistral : la Files API de Mistral (upload persistant, référencé ensuite par `file_id`, conservé jusqu'à suppression explicite) n'est jamais utilisée. Ça ne veut pas dire que le fichier lui-même n'est jamais transmis à Mistral — pour un PDF (endpoint `/v1/ocr`, appel stateless, modèle `mistral-ocr-latest`) et pour une image (appel vision `document_url`/`image_url` en chat completions), le fichier est bien envoyé, parce qu'il n'existe pas d'alternative pour en obtenir l'analyse. Seuls Word et Excel ne quittent jamais la VM centrale, extraits localement (`python-docx`, `openpyxl`).

Le Zero Data Retention n'est **jamais actif par défaut**, y compris pour l'OCR : c'est une option à demander explicitement au support Mistral (facturation à l'usage, approbation à leur discrétion). Elle est *éligible* pour l'OCR et le chat completions texte une fois activée, mais **structurellement exclue** pour le chemin vision (image), quoi qu'il arrive. Cette ADR n'attend donc pas du ZDR qu'il protège tout le pipeline par défaut — elle pose seulement que le fichier ne doit jamais être *stocké durablement* côté Mistral au-delà de l'appel ponctuel qui le traite.

Ce choix prolonge le raisonnement déjà posé par [ADR-0002](0002-relais-central-mistral.md) et par la spec [1.1.1](../specs/v1.1.1-persistance-conversations.md) (qui a écarté l'API Agents & Conversations de Mistral pour le même motif) : la VM centrale utilise une seule clé API Mistral partagée par tout le cabinet, sans notion de sous-compte côté Mistral. Un fichier stocké durablement chez Mistral via sa Files API reproduirait exactement le problème d'isolation entre comptes déjà écarté pour les conversations — un fichier potentiellement lié à un client du cabinet ne doit pas dépendre d'un stockage tiers sans garde-fou d'isolation.

## Consequences

Le pipeline d'extraction (module `vm_centrale/analyse_pieces_jointes/`) devient un passage obligé avant tout envoi de pièce jointe à Mistral, pour tout usage futur (y compris les futurs Agents IA par pôle, 1.3.0+) : aucun code ne doit référencer un `file_id` Mistral persistant dans un appel de chat, ni supposer qu'un fichier déjà envoyé reste disponible côté Mistral d'un appel à l'autre. Seule exception assumée : l'analyse d'image, structurellement hors Zero Data Retention (pas seulement « pas encore activée ») faute d'alternative — à documenter explicitement à chaque nouvel usage qui s'appuierait dessus, jamais à généraliser silencieusement aux autres formats. Activer réellement le ZDR pour l'OCR et le chat (demande à faire côté compte Mistral du cabinet, hors périmètre de ce projet logiciel) reste une action de suivi non bloquante pour cette version.
