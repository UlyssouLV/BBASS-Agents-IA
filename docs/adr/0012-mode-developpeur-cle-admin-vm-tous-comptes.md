# Le Mode développeur donne accès à toutes les conversations, tous comptes, derrière la seule Clé d'administration VM

Jusqu'ici, une conversation et ses pièces jointes sont strictement privées à leur compte : ni un autre compte, ni même un compte administrateur, n'y accède ([CONTEXT.md](../../CONTEXT.md)). La V1.3.0 introduit un Mode développeur (inspecteur des échanges avec le modèle) qui rompt délibérément cette règle : une fois débloqué par la Clé d'administration VM (`VM_ADMIN_KEY`, [ADR-0007](0007-cle-admin-vm-reutilisee-poste.md)), il donne accès au contenu technique complet — payload envoyé, réponse brute, pièces jointes référencées — de **toutes** les conversations de **tous** les comptes, pas seulement celles du compte qui l'ouvre.

Deux alternatives écartées : restreindre l'accès au compte administrateur (`est_admin`) comme l'onglet Consommations le fait déjà pour ses agrégats — rejeté car un compte administrateur n'est, par ailleurs, pas plus légitime qu'un autre pour lire le contenu métier d'une conversation, et ce n'est pas la distinction qui importe ici (c'est un outil de débogage technique, pas un droit métier) ; introduire un nouveau flag « dev » sur `Compte` — rejeté pour ne pas ajouter un second axe de rôle au modèle de comptes pour un outil qui n'a vocation à être utilisé que par qui développe le logiciel.

## Consequences

`VM_ADMIN_KEY` porte une troisième responsabilité, après la révocation forcée de jetons (V1) et les actions sensibles de gestion de comptes (V1.1, [ADR-0007](0007-cle-admin-vm-reutilisee-poste.md)) : quiconque la détient peut désormais aussi lire le contenu complet de n'importe quelle conversation de n'importe quel compte via le Mode développeur, au-delà de ce qu'un compte administrateur ordinaire peut voir. La confidentialité par compte (Conversation, Pièce jointe) n'est plus absolue : elle devient « privée à son compte, sauf via le Mode développeur ». Un futur lecteur ne doit pas supposer qu'aucun tiers que le compte lui-même ne peut jamais lire une conversation — c'est vrai dans l'interface normale, pas derrière cette clé. Si cette clé fuit, l'exposition ne se limite plus à la gestion des comptes : elle couvre tout le contenu métier échangé avec l'IA.
