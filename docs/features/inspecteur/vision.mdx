# Vision

## Qu’est-ce que c’est

**Vision** : analyse d’une **image** jointe (photo, capture d’écran, plan scanné en JPG/PNG…). Le modèle regarde l’image, **transcrit le texte visible** et **décrit** ce qui est exploitable (schéma, tableau, photo de terrain…), en français. Le résultat est un texte (`contenu_extrait`) que le [Chat](./chat.mdx) pourra utiliser — pas l’image elle-même dans les tours suivants.

Ce n’est **pas** un outil demandé par le modèle : c’est une [étape de traitement](/docs/glossaire#etape-de-traitement) imposée par la VM **au moment où** le collaborateur joint une image.

## Pourquoi

Sans cette étape, le Chat ne verrait que le nom du fichier (« photo.jpg ») et inventerait ce qu’il contient. Il faut donc une description **avant** le premier appel de chat du tour.

Contrairement à l’[OCR](./ocr.mdx) sur PDF :

| | OCR (PDF) | Vision (image) |
| --- | --- | --- |
| Endpoint | `/v1/ocr` dédié | `chat/completions` (comme le Chat) |
| Modèle | **Autre** : `mistral-ocr-latest` | **Le même** que le Chat (`mistral-small-2603`) |
| Entrée | document PDF en base64 | consigne texte + `image_url` base64 |
| Sortie | markdown page par page | JSON structuré (`contenu_extrait`, `echec_analyse`) |
| Facturation | à la **page** | au **token** (Consommation `vision`) |

Pas de modèle « Pixtral » séparé aujourd’hui : c’est le modèle de chat en multimodal. La carte Inspecteur reste libellée **Vision** (`type_appel = vision`) pour la distinguer du Chat de réponse.

L’image est envoyée **inline** pour cet appel, jamais via une Files API persistante ([ADR-0009](/docs/adr/0009-pieces-jointes-jamais-mistral-files-api)). L’original reste sur la VM. Ce chemin vision est **hors** Zero Data Retention (contrairement à l’OCR / chat texte une fois le ZDR activé côté fournisseur).

## Où ça se place

Au **tour d’envoi** avec une pièce jointe image ([aperçu](./apercu.mdx)) :

1. **Vision** (cette carte) — description / transcription.
2. **Chat** — reçoit l’extrait dans un message `system` (« Pièce jointe … »), pas l’image brute.
3. Suite habituelle (outils, garde-fous, titrage / résumé selon le cas).

Les tours suivants ne refont **pas** la vision : le texte est déjà en base. Pour le relire hors fenêtre, le modèle peut demander `relire_pieces_jointes` (carte [Outil](./outil.mdx)), sans nouvel appel vision.

Si l’image est illisible ou sans contenu utile, le modèle peut renvoyer `echec_analyse: true` avec une brève explication dans `contenu_extrait` — ce n’est pas une erreur HTTP : l’échange peut rester en succès, avec un extrait qui dit pourquoi ça ne sert pas.

## Exemple concret

Le collaborateur joint une capture de carte (zone autour de Castries) et demande :

> Qu’est-ce qu’on voit sur cette image ?

Dans l’inspecteur, **avant** le Chat :

    </p>
    <p>
      Consigne : transcrire le texte visible et décrire le contenu exploitable

## Ce qui n’est pas de la vision

| Fichier | Traitement | Carte |
| --- | --- | --- |
| **Image** | Vision (chat multimodal) | Cette page |
| **PDF** | [OCR](./ocr.mdx) (autre modèle, autre endpoint) | OCR |
| **Word** / **Excel** | Extraction **locale** sur la VM, **aucun** appel au fournisseur | Aucune carte Vision |
