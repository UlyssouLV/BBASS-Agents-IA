# ecriture_annoncee

Seule une vraie Carte de confirmation, ouverte par `ecrire_moduleo`, et son statut (« Écrit dans Moduléo », « Annulée… », « Expirée… », refus) disent une écriture Moduléo. Le texte du modèle ne peut ni montrer une carte, ni dire une écriture faite.

- `annonce_une_carte` : la réponse parle d'une carte de confirmation, ou autrement (« prête à être confirmée », « la carte qui s'affiche », « validez-la / confirmez sur la carte », #259), d'un bouton (« Valider pour appliquer », « confirmez pour enregistrer »), écrit une requête d'écriture (« POST moduleo/tacheafaire », bloc JSON avec `"route"`, `"methode"` ou `"corps"`, ou une ligne « Route : », « Méthode : », « Paramètre(s) : », « Corps : » suivie d'une méthode, d'une route, de « champ = valeur » ou d'un JSON, #259 ; pas « Méthode : on calcule » ni « Route : D613 »), ou demande une confirmation en texte sur Moduléo ou l'un de ses éléments (« Souhaitez-vous / Voulez-vous que je crée / procède / ajoute… », « Confirmez la création / l'ajout / le déplacement… », #259 ; aussi « … que je procède ? », sans objet ; pas « Confirmez-vous qu'il s'agit… ? » ni « que je crée un modèle de courrier ? »).
- `affirme_une_ecriture(reponse, routes_confirmees, sans_nommer_moduleo)` : la réponse dit un élément « créé / écrit / ajouté / modifié / supprimé / enregistré / mis à jour / saisi / déplacé dans (ou sur) Moduléo », ou, sans nommer Moduléo, « est / a été (bien) supprimé(e) » le participe en fin de phrase (« La note … est supprimée. », #259 ; « créée le 3 mars » reste une fiche lue), hors lecture : pas de négation dans la même proposition (« Aucun contact … n'est enregistré dans Moduléo », « n'a pas été créé », « aucun téléphone enregistré »), ni un état lu sur une fiche, « est / sont (bien, déjà) enregistré dans Moduléo » sans « a été » (#258). `routes_confirmees` (`moduleo/ecritures.routes_confirmees`) : une phrase qui ne nomme aucun élément (« Écrit dans Moduléo. »), ou l'élément d'une de ces routes (« le numéro est enregistré » après `moduleo/telephone`), redit un résultat et ne compte pas (#259) ; tous les segments de la route comptent (l'e-mail de `cogeo/elementged/email`). `sans_nommer_moduleo` faux, quand `ecrire_moduleo` n'est pas proposé au tour (prod, compte sans route ouverte) : seule une phrase qui nomme Moduléo compte, « Le fichier a été supprimé. » parle d'autre chose.
- `retirer_ecriture_affirmee` : retire chaque phrase qui affirme une écriture, et chaque route, paramètre ou corps écrit en texte (#259) ; si plus rien ne reste, `PHRASE_CARTE_OUVERTE`.

**Règles** (`routers/conversations.py`).

1. **Relance forcée** (`_resoudre_reponse_chat`, `_a_relancer`) : une réponse finale du modèle qui annonce une carte, ou affirme une écriture autre que le résultat d'une écriture `confirmee` de la Conversation, sans aucune carte ouverte dans le tour (`ContexteTour.cartes_du_tour`), n'est jamais montrée. Si `ecrire_moduleo` est proposé au tour, la VM refait l'appel avec le même historique, plus un message système qui n'est jamais enregistré (`_CONSIGNE_RELANCE` : la réponse annoncée a été écartée, seul `ecrire_moduleo` ouvre une carte, lire d'abord la fiche d'un élément nommé dont l'id manque, ne jamais deviner un id), et un outil imposé quelconque (`tool_choice` Mistral `"any"`). Troisième passage de #206 : avec `ecrire_moduleo` imposé, le modèle sans l'id visé fabriquait la requête (`[id Moduléo 15]`, 3 rejeux sur 3) ; libre de l'outil, il cherche d'abord le contact (4 sur 4). Les tours ordinaires qui suivent proposent les outils : soit une carte s'ouvre, soit l'outil refuse et le modèle répond d'après ce refus. Une seule relance par message ; elle s'ajoute aux tours ordinaires si besoin (`_TOURS_APRES_RELANCE`, 4 : relance, lecture, champs, écriture, puis la réponse), le dernier appel partant toujours sans `tools`. L'appel imposé est borné (`config.py`) : `MISTRAL_RELANCE_MAX_TOKENS` (1 024 tokens générés, `max_tokens` Mistral) et `MISTRAL_RELANCE_TIMEOUT` (20 s, à la place de `MISTRAL_HTTP_TIMEOUT`). S'il échoue ou expire, l'échec est journalisé à l'inspecteur sans faire tomber le tour, et la réponse annoncée devient la phrase fixe (règle 2) (#258).
2. **Phrase fixe** (`_appliquer_garde_fous`, en tête) : sans carte dans le tour, une réponse qui annonce encore une écriture (après la relance, ou sans outil d'écriture proposé) devient `PHRASE_ECRITURE_NON_PROPOSEE`. Elle compte parmi les phrases fixes (titrage sur le seul message).
3. **Carte ouverte** : `retirer_ecriture_affirmee` sur la réponse, rien n'est encore écrit avant le clic, et la seule carte est la vraie.

Après une écriture `confirmee` dans la Conversation, le modèle peut redire son résultat (« le téléphone a été ajouté dans Moduléo », « le numéro est enregistré ») : ce n'est pas relancé. Une écriture dite faite sur un autre élément (« La note … est supprimée. » après un téléphone) l'est (#259).

**Depuis.** 1.5.2 (#252). Faux positifs de lecture et relance bornée : #258 (second passage de #206 : « Aucun contact Client Exemple 10 n'est enregistré dans Moduléo. » relancé, puis 8 868 tokens en 76 s et « service indisponible »). Origine : premier passage des tests humains de la 1.5.2 (#206) : fausse carte en texte (bloc JSON `POST moduleo/tacheafaire`, « Voici la carte de confirmation… Valider pour appliquer ») sans appel de l'outil, et « la tâche … a été créée dans Moduléo » alors que rien n'était écrit.

Autres tournures, confirmation en texte, fausse carte à côté de la vraie et exception bornée à l'élément confirmé : #259 (second passage de #206 : « prête à être confirmée », « Validez-la sur la carte qui s'affiche », « La note … est supprimée. », « Route : PUT moduleo/telephone/{idTelephone} / Paramètre : idTelephone = 152 », « Souhaitez-vous que je procède à la saisie… ? »).

Limites connues : une écriture inventée dite comme un état suivi d'autre chose (« la tâche est enregistrée dans Moduléo », « la note est supprimée depuis ce matin ») n'est pas reconnue. Une affirmation tournée autrement (« c'est fait », « j'ai enregistré la tâche ») n'est pas reconnue. Après une confirmation dans la Conversation, une autre écriture sur le même élément (une note créée, puis « la note est supprimée ») passe aussi. Une question de clarification réelle tournée « Souhaitez-vous que je crée… ? » sur un élément de Moduléo est relancée avec l'outil imposé. Avec `ecrire_moduleo` proposé, une phrase hors Moduléo au participe final (« Le fichier a été supprimé. ») est aussi relancée, puis remplacée par la phrase fixe : le garde-fou préfère ce faux positif à une écriture inventée sous un pronom (« Elle a été créée. »).

Code : `garde_fou.py`.
