# rechercher_web

Cherche sur Internet quand le modèle le décide. `requete` seule part vers `MoteurRecherche` (`moteur_recherche.py`, SearXNG par défaut). `besoin` ne va qu'à l'appel d'extraction (ADR-0013).

**Éligibilité.** Toujours, sur chaque appel de chat principal (premier message compris). Jamais sur le titrage ni le résumé et profil.

**Déroulé.**

1. Les 5 premiers résultats (titre, URL, extrait du moteur). Moteur injoignable : « Recherche indisponible… ». Aucun résultat, ou requête vide : « Aucun résultat… ». Jamais une erreur HTTP.
2. Les 3 premières pages. Depuis la 1.4.3 (#154, ADR-0015), le cache commun des pages web d'abord (`cache_pages.py`, table `cache_pages_web`, une ligne par URL exacte, partagée entre tous les comptes et tous les pôles) : une copie de moins de 24 h (`VALIDITE_CACHE_PAGES`, `config.py`) remplace le téléchargement ; une copie plus vieille est ignorée, jamais purgée pendant la requête. Sinon téléchargement, en parallèle (`TelechargeurPages`, `telechargement_pages.py`, 10 s au plus par page). Une page lue avec succès (200, HTML, texte principal non vide) est écrite dans le cache avec son titre, avant tout plafond (insertion ou écrasement : la dernière écriture l'emporte). Échec (délai, statut HTTP, contenu non HTML, PDF compris, aucun texte principal) : jamais mis en cache, la page est ignorée, son extrait de moteur reste. Le cache ne garde que le texte et le titre, jamais l'extrait ni les questions couvertes (elles portent le `besoin` d'un compte), et la conversation garde sa propre copie (étape 4), qui ne suit jamais le cache. Cache, téléchargement et nettoyage (étapes 2 et 3, `lire_pages`) partagés avec `lire_pages_web` pour une URL écrite par le compte (#140), pas dupliqués. Certificats vérifiés avec le magasin du système (`truststore`), pas `certifi` : sous Windows et macOS, il complète la chaîne d'un serveur qui n'envoie pas son certificat intermédiaire, fréquent sur les sites publics. Limite : sous Linux, le magasin du système ne la complète pas, à revoir au déploiement (1.6.0).
3. Texte principal via trafilatura, jamais coupé page par page. Plafond global, pour une page servie par le cache comme pour une page téléchargée de 80 % de la fenêtre du modèle d'extraction (fiche `MODELE_CHAT`, 262 144 tokens), en vrais tokens depuis la 1.4.2 (#146) : chaque page lue est comptée par le tokenizer de la fiche (`compter_tokens`, `compte_tokens.py`). Tant que le total dépasse le plafond, la dernière page lue est retirée entière. En 1.4.0, plafond estimé en caractères (3 caractères ≈ 1 token).
4. Résultats et texte nettoyé des pages lues dans `resultats_recherche_web` (source du garde-fou chiffres). Une page retirée par le plafond n'est pas une source.
5. Appel d'extraction (`MODELE_CHAT`, ADR-0014) : consigne fixe `CONSIGNE_EXTRACTION`, puis `besoin` et les pages lues, jamais le contexte de la conversation. Ligne `Consommation` `extraction_web` et échange d'inspecteur `extraction_web` (origine `mistral`). Aucune page lue : pas d'appel. Depuis la 1.4.1, sortie JSON stricte (`response_format`) : `extrait` et `questions_couvertes` (question, réponse, source URL). Les 8 premières questions seulement, réponse coupée à 300 caractères (`_QUESTIONS_MAX`, `_REPONSE_MAX`), enregistrées dans `questions_couvertes` (origine `initiale`) sur le résultat de la page source. Une question dont la source n'est pas une page lue est ignorée. Extraction en échec ou réponse hors du JSON attendu : « Extraction indisponible… », sans questions.
6. Le modèle principal reçoit la liste (titre, URL) et l'extrait, jamais le texte des pages. L'extrait n'est pas une source des garde-fous. Sans extraction réussie, la liste part avec les extraits du moteur.

**Inspecteur local** (`outil:rechercher_web`) : arguments, résultats bruts (`resultats`) ou `erreur`, pages (URL, statut, taille en caractères, `tokens`, `retiree_par_plafond`, erreur, `origine` `cache` ou `telechargement`, et pour le cache `age_copie_secondes`, l'âge de la copie servie), contenu renvoyé au modèle.

**Depuis.** 1.4.0 (sortie JSON et questions couvertes : 1.4.1, #136 ; cache commun des pages : 1.4.3, #154). Spec 1.4.0, ADR-0013 : le relais `chat/completions` n'a pas l'outil `web_search` de Mistral ; le modèle décide de chercher (décision n° 3).

Code : `outil.py`. D'autres modules de cet outil (plafond, extraction, …) peuvent vivre à côté sans changer le registre (`OUTIL` et `CONSIGNE_EXTRACTION` restent exportés par ce paquet).
